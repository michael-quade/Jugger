A
Fix the localStorage Time Bomb
✓ Implemented Effort: Medium Prevents Data Loss
Problem
The entire Zustand store — including base64 images and all archived years' match data — was serialized to localStorage on every state change with no filter. Silent QuotaExceededError at 5–10 MB with no user warning.
What was done
  • Added partialize to persist() — excludes archivedYears and liveCache entirely
  • Strips imageData / scorecardImageData from courses and courseHistory
  • Strips photoData from holeInOnes
  • All excluded data lives in Supabase and is restored on first fetch
Note: Images show a brief flash on cold load until Supabase responds. In offline/PWA mode, images won't appear until reconnected — acceptable tradeoff for a tournament scoring app.
B
Code Splitting & Lazy Loading
✓ Implemented Effort: Low Faster Load for All Users
Problem
All 22 pages imported statically in App.tsx. Recharts (~230 kB gzip) and every admin page shipped in the initial bundle to every user on every page load.
What was done
  • 21 pages converted to React.lazy() — only Dashboard stays eager
  • <Suspense> wrapper with a green spinner fallback added
  • Recharts isolated in its own chunk via manualChunks in vite.config.ts
  • Main bundle now 114 kB gzip; Recharts (165 kB) only downloads on Analytics
C
Supabase Sync Architecture Cleanup
Remaining Effort: Medium Stability During Live Scoring
Problem
Four issues compound during live scoring: (1) app_state blob still risks hitting Supabase's 1 MB realtime broadcast limit as images accumulate. (2) Match scores upsert per-keystroke with no debounce. (3) The 10-second poll runs on every page. (4) After finalizeYear(), the sync hook goes inert until page reload.
Fix
  • Add 500ms debounce to match upserts
  • Gate the 10-second poll to Scorecards page only
  • Move YEAR to a useRef updated by a store subscriber so year advances don't break sync mid-session
D
Analytics Performance
✓ Implemented Low Effort
Problem
courseHistoryTyped was recomputed in the render body on every render (no useMemo). It was a dependency for 6 of the 9 analytics memos — any re-render invalidated all 6 unnecessarily.
What was done
  • Wrapped courseHistoryTyped in useMemo([courseHistory])
  • The 6 dependent memos now only recompute when course history actually changes, not on every render
E
Security Hardening
Remaining Effort: Medium–High Pick your level
Problem
Admin password hashes are unsalted SHA-256 in the anon-key-readable app_state Supabase column — extractable with browser devtools. Two plaintext default passwords hardcoded in source. Auth session is localStorage-only with no server-side validation.
Fix options — pick your level
  • Minimal: Add per-user salt; move admins[] to a separate Supabase table with RLS
  • Better: Replace homebrew auth with Supabase Auth (magic link or password)
  • Pragmatic minimum: Move hardcoded default passwords to environment variables
F
ScorecardCard Render Optimization
✓ Implemented Low Effort Mobile Smoothness
Problem
getPlayerCourseHdcp() called 4× per render, each recomputing Math.min(...allPlayers) internally. formatLabel object recreated on every render. Both fired on every score entry keystroke during live scoring.
What was done
  • playerHdcps computation wrapped in useMemo keyed on player IDs, teams, course, and config — not scores. Memo skips entirely during score entry
  • formatLabel wrapped in useMemo keyed on gc values
  • Removed redundant top-level allPlayers = teams.flatMap() call (now only computed inside the memo)
G
Store Migration Cleanup & Type Safety
✓ Implemented Low Effort
Problem
Migration blocks were out of order in source: v22 and v27 appeared after v31, making the migration history unreadable and future edits error-prone. The SideBetConfig discriminant was also flagged.
What was done
  • Migration blocks reordered into strict numeric sequence: …21, 22, 23, 24, 25, 27, 29, 31
  • SideBetConfig discriminant union skipped — adding kind requires a store v32 migration + cascading type changes across 4 files; risk outweighs benefit
